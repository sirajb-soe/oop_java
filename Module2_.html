01 · Classes & Objects
CLASSES & OBJECTS
01 · Classes & Objects

What Is a Class?

A class is a user-defined blueprint that groups related data (fields) and behavior (methods) into a single unit.

01 · Classes & Objects

In Simple Words

• A class defines the structure — what data and actions an object will have.
• An object is a real instance created from a class, with its own copy of the data.
• We access an object's members using the dot (.) operator.
• Many objects can be created from the same class.
Think of a class as a blueprint and objects as houses built from that blueprint.
01 · Classes & Objects

Key Points

01

Class

A blueprint that defines fields and methods.

02

Object

A concrete instance created from a class using new.

03

Reference Variable

A variable that stores the address of an object, not the object itself.

01 · Classes & Objects

Class vs Object vs Reference

Class

Defined once; describes structure and behavior.

Object

Created as many times as needed; occupies memory on the heap.

Reference Variable

Stored on the stack; points to the object on the heap.

01 · Classes & Objects

General Syntax

General Syntax
class ClassName {
    // fields (data)
    // methods (behavior)
}

ClassName obj = new ClassName();
01 · Classes & Objects

Understanding the Syntax

•class — the keyword that begins a class definition.
•ClassName — the name of the blueprint; by convention it starts with a capital letter.
•{ fields; methods; } — the class body, where data and behavior are written.
•ClassName obj — declares a reference variable of that type.
•new ClassName() — creates the actual object in memory and gives obj its address.

02 · Methods
METHODS
02 · Methods

What Is a Method?

A method is a named block of code inside a class that performs a specific task and can be called (invoked) whenever that task is needed.

02 · Methods

In Simple Words

• A method has a name, an optional list of parameters, and a return type (or void).
• Parameters are placeholders; arguments are the actual values passed when calling.
• A method can return a single value using return, or return nothing (void).
• Methods avoid rewriting the same code again and again.
A method groups a task once and lets you reuse it as many times as you like.
02 · Methods

Key Points

01

Declare

Define a name, parameters, and a return type.

02

Call

Invoke the method using its name and arguments.

03

Return

Send a value back to the caller using return.

02 · Methods

General Syntax

General Syntax
returnType methodName(parameterType parameterName) {
    // method body
    return value; // omit this line if the method is void
}
02 · Methods

Understanding the Syntax

•returnType — the data type of the value sent back, or void for none.
•methodName — the name used to call this method.
•(parameterType parameterName) — the inputs the method needs, listed in parentheses.
•{ ... } — the method body containing the statements to execute.
•return value; — sends a value back to the caller; skipped entirely for void methods.

03 · Constructors
CONSTRUCTORS
03 · Constructors

What Is a Constructor?

A constructor is a special method that initializes a new object. It has the same name as the class and no return type, not even void.

03 · Constructors

In Simple Words

•Same name: a constructor's name must exactly match the class name.
•No return type: not even void.
•Runs automatically when an object is created with new.
•Default is provided by Java if you write no constructor at all.
Constructors are about initializing state, not computing a result to return.
03 · Constructors

Three Types of Constructors

01

Default

No-argument constructor that sets initial/default values.

02

Parameterized

Accepts arguments to initialize fields with specific values.

03

Copy

Creates a new object by copying values from another object of the same class.

03A · Default Constructor

Default Constructor

A constructor with no parameters. If a class defines no constructor at all, Java automatically supplies one that sets fields to their default values (0, null, false).

03A · Default Constructor

General Syntax

General Syntax
class Student {
    String name;
    int marks;

    Student() {
        name = "Unknown";
        marks = 0;
    }
}
03A · Default Constructor

Understanding the Syntax

•Student() — no parameters inside the parentheses.
• Runs automatically when new Student() is used with no arguments.
• Typically sets fields to safe starting values.

Copy Constructor

A constructor that creates a new object by copying the field values of an existing object of the same class. Java does not auto-generate one — you write it yourself.

03C · Copy Constructor

General Syntax

General Syntax
Student(Student other) {

03C · Copy Constructor

Understanding the Syntax

• The single parameter (other) is of the same class type as the object being built.
•other.name reads the existing object's field.

04 · this Keyword
THIS KEYWORD
04 · this Keyword

What Is this?

this is a reference to the current object — the object whose method or constructor is currently executing.

04 · this Keyword

In Simple Words

• Resolves naming conflicts when a parameter has the same name as a field.
•this.fieldName refers to the object's field; fieldName alone refers to the parameter.
•this(...) can call another constructor of the same class (constructor chaining).
•this can be passed as an argument to represent "the current object."
04 · this Keyword

Key Points

01

Disambiguation

this.name refers to the field; name alone refers to the parameter.

02

Constructor Chaining

this(...) calls another constructor of the same class.

03

Passing Self

this can be passed to another method or constructor.

04 · this Keyword

General Syntax

General Syntax
ClassName(dataType name) {
    this.name = name;
}
04 · this Keyword

Understanding the Syntax

•this — refers to the object currently being built.
•this.name — the object's own field (left side of the name clash).
•name (without this) — the constructor's parameter (right side).
•this.name = name; — copies the incoming parameter value into the object's field.
04 · this Keyword

Example 1 · Resolving a Name Clash

class Student {
    String name;

    Student(String name) {
        this.name = name;
    }
}

public class Main {
    public static void main(String[] args) {
        Student s = new Student("Asha");
        System.out.println(s.name);
    }
}

Asha

Example 2 · Constructor Chaining With this()

class Student {
    String name;
    int marks;

    Student() {
        this("Unknown", 0);
    }

    Student(String name, int marks) {
        this.name = name;
        this.marks = marks;

05 · Garbage Collection
GARBAGE COLLECTION
05 · Garbage Collection

What Is Garbage Collection?

Garbage collection is Java's automatic process of reclaiming memory occupied by objects that are no longer reachable by any reference.

05 · Garbage Collection

In Simple Words

• Objects are created on the heap using new.
• An object becomes eligible for garbage collection once no reference points to it.
• The JVM's Garbage Collector (GC) automatically reclaims that memory.
• Unlike C/C++, Java programmers do not manually free memory.
Setting a reference to null often makes the previously referenced object eligible for garbage collection.
05 · Garbage Collection

Key Points

01

Allocate

new creates an object on the heap.

02

Unreachable

No variable refers to the object anymore.

03

Reclaim

The JVM's GC frees that memory automatically.

05 · Garbage Collection

Good to Know

No delete Keyword

Java has no manual free()/delete like C/C++ — the JVM manages memory automatically.

finalize() (Legacy)

An old hook the GC could call before reclaiming an object; not relied upon in modern Java.

05 · Garbage Collection

Example 1 · Clearing a Reference

class Student {
}

public class Main {
    public static void main(String[] args) {
        Student s = new Student();
        s = null;
        System.out.println("Reference cleared");
    }
}

06 · Method Overloading
METHOD OVERLOADING
06 · Method Overloading

What Is Method Overloading?

Method overloading allows a class to have multiple methods with the same name, as long as their parameter lists differ.

06 · Method Overloading

In Simple Words

• Overloaded methods must differ in the number, type, or order of parameters.
• The return type alone is not enough to distinguish overloaded methods.
• Java decides which overloaded method to call at compile time, based on the arguments.
• This is also called compile-time (static) polymorphism.
Same name, different parameter signature — Java resolves the right one automatically.
06 · Method Overloading

Ways to Overload

01

Number of Parameters

add(int, int) vs add(int, int, int)

02

Type of Parameters

add(int, int) vs add(double, double)

03

Order of Parameters

display(String, int) vs display(int, String)

06 · Method Overloading

General Syntax

General Syntax
returnType methodName(TypeA a) {
    // version 1
}

returnType methodName(TypeA a, TypeB b) {
    // version 2 — different parameter list
}
06 · Method Overloading

Understanding the Syntax

• The same methodName is repeated for each overloaded version.
• Each version has a different parameter list — number, type, or order.
• Java automatically chooses the matching version based on the arguments used in the call.
06 · Method Overloading

Example 1 · Different Number of Parameters

public class Main {
    static int add(int a, int b) {
        return a + b;
    }

    static int add(int a, int b, int c) {
        return a + b + c;
    }

    public static void main(String[] args) {
        System.out.println(add(10, 20));
        System.out.println(add(1, 2, 3));
    }
}

07 · Passing & Returning Objects
PASSING & RETURNING OBJECTS
07 · Passing & Returning Objects

Objects as Parameters and Return Values

Just like primitive values, objects can be passed into methods and returned from methods.

07 · Passing & Returning Objects

In Simple Words

• When an object is passed to a method, the reference (address) is copied — both variables point to the same object.
• Changes made to the object's fields inside the method are visible after the method returns.
• A method can also create and return a new object using its return type as the class name.
• Reassigning the parameter itself inside the method does not affect the caller's reference.
Java is always pass-by-value — but for objects, the "value" passed is the reference itself.
07 · Passing & Returning Objects

Key Points

01

Pass

Object reference is copied into the parameter.

02

Modify

Changes to fields are visible to the caller.

03

Return

A method can create and return a new object.

07 · Passing & Returning Objects

General Syntax

General Syntax
void methodName(ClassName obj) {
    obj.field = newValue; // modifies the same object the caller has
}

ClassName methodName() {
    ClassName obj = new ClassName();
    return obj;
}
07 · Passing & Returning Objects

Understanding the Syntax

•ClassName obj as a parameter — receives a copy of the reference, pointing to the same object.
•obj.field = newValue; — the change is visible to the caller because it is the same object.
•return obj; — sends a newly created object back; the return type must be the class name.
07 · Passing & Returning Objects

Example 1 · Passing an Object

class Student {
    String name;
    int marks;
}

RECURSION
08 · Recursion

What Is Recursion?

Recursion is a technique where a method calls itself to solve a smaller version of the same problem.

08 · Recursion

In Simple Words

• Every recursive method needs a base case — a condition where it stops calling itself.
• The recursive case reduces the problem and calls the method again.
• Each call is placed on the call stack until the base case is reached.
• Without a base case, recursion never ends and causes a StackOverflowError.
Base case first, recursive case second — always.
08 · Recursion

Key Points

01

Base Case

Stops the recursion.

02

Recursive Case

Calls itself with a smaller problem.

03

Call Stack

Each call waits until the one below it returns.

08 · Recursion

General Syntax

General Syntax
returnType methodName(parameters) {
    if (baseCondition) {
        return baseResult;
    }
    return methodName(smallerProblem);
}
08 · Recursion

Understanding the Syntax

•if (baseCondition) — checks whether the recursion should stop.
•return baseResult; — the fixed answer once the base case is reached.
•return methodName(smallerProblem); — the method calls itself again with a reduced problem.
08 · Recursion

Example 1 · Factorial

public class Main {
    static int factorial(int n) {
        if (n == 0) {
            return 1;
        }
        return n * factorial(n - 1);
    }

    public static void main(String[] args) {
        System.out.println(factorial(5));
    }
}

        System.out.println(sum(5));
    }

09 · Access Control

What Is Access Control?

Access modifiers control which parts of a program can see and use a class, field, method, or constructor.

09 · Access Control

In Simple Words

• Every field, method, and constructor can carry an access modifier.
• Java has exactly four levels: public, protected, default, and private.
• Restricting access protects data from being changed in unsafe or unexpected ways.
Order from most open to most restrictive: public → protected → default → private.
09 · Access Control

The Four Access Modifiers

public

Accessible from anywhere the class is accessible.

private

Accessible only within the same class.

protected

Accessible within the same package and by subclasses, even in other packages.

default

No modifier written; accessible only within the same package.

The static Keyword

static members belong to the class itself rather than to any single object — they are shared across all objects of that class.

10 · static

In Simple Words

• A static field has exactly one copy, shared by every object of the class.
• A static method can be called using the class name, without creating an object.
• static members are loaded into memory when the class is loaded.
Use static for things that belong to the class as a whole, not to one specific object.

Understanding the Syntax

•static before a field or method means it belongs to the class, not to individual objects.
• Access a static member through the class name, e.g. Counter.count.
• No object needs to be created to use a static member.

NESTED & INNER CLASSES
11 · Nested & Inner Classes

What Is a Nested Class?

A nested class is a class declared inside another class. It logically groups classes that are used in only one place, improving encapsulation.

11 · Nested & Inner Classes

In Simple Words

• A nested class lives inside another class, called the outer class.
• A static nested class does not need an outer object to exist.
• A non-static (inner) class is tied to a specific outer object and can use its members directly.
11 · Nested & Inner Classes

Two Main Kinds

Static Nested Class

Declared with static; does not need an instance of the outer class to be created.

Inner (Non-Static) Class

Belongs to a specific instance of the outer class; can directly access the outer object's members.

11 · Nested & Inner Classes

General Syntax

Static Nested Class
class Outer {
    static class Nested {
        // members
    }
}

Outer.Nested obj = new Outer.Nested();
11 · Nested & Inner Classes

Understanding the Syntax

•static class Nested — declared inside Outer, marked static.
•Outer.Nested — the nested class is referred to through the outer class name.
•new Outer.Nested() — created without needing an Outer object first.

12 · Four Pillars of OOP

Object-Oriented Programming Rests on Four Ideas

Every object-oriented language, including Java, is built around four core principles that work together to model real-world entities.

12 · Four Pillars of OOP

In Simple Words

•Encapsulation — keep data safe by hiding it and controlling access.
•Inheritance — build new classes on top of existing ones.
•Abstraction — show what something does, hide how it does it.
•Polymorphism — let the same name behave differently depending on context.
12 · Four Pillars of OOP

The Four Pillars

Encapsulation

Bundling data and methods together, and hiding internal details using access modifiers like private.

Inheritance

Allowing one class to acquire the fields and methods of another, enabling reuse.

Abstraction

Showing only essential features while hiding complex implementation details.

Polymorphism

Allowing the same method name or reference to behave differently in different situations.
